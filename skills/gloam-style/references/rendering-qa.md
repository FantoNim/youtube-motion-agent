# Rendering and QA gates

This skill is documentation/templates only. No Gloam sample or end-user production render was requested or produced when it was authored. A separate technical 3D fixture does not approve this treatment. Read the installed Remotion/Filmcraft workflow before actual production; use existing adequate local solutions.

## Preflight

- Inspect existing project/source/lockfile/scripts and current dependency/runtime reports. Keep source video read-only; version all derived outputs outside its entire source folder. Verify enough disk/RAM for actual render size. A renderer skill being installed is not runtime proof.
- Confirm licensing: fonts, logos, footage, documents, music/models, and Remotion's applicable license separately from this guide. Do not assume online reference access permits republication or that stylistic analysis grants asset rights. No paid/cloud render, upload or global install is implicit.
- Use local approved assets. No source screenshots or audio are bundled here. For source-screen excerpts follow current user privacy/framing directives. Keep style labels and internal evidence paths off the learner frame.
- Match target aspect and actual speech duration; vertical is a redesign. Use the measured recording as the clock, with optional script and verified cue ranges. Resolve material track/rights ambiguity before irreversible work.

## Sample gate

Typecheck/build through the actual project scripts; render a 5–12s representative excerpt with real supplied narration when present. Include both an evidence card and a planned geometry beat if both are in scope. Inspect source stills for layout, then the **encoded** moving output for transition/occlusion and actual audio by an available authorized playback route. No invented “looks good” from a successful process exit. Record approval as pending until the user approves or explicitly waives it.

For geometry, additionally inspect camera start/mid/end, door closed/half-open/open, node connectors, contact shadows, silhouette separation and any label projection. A still cannot establish correct camera motion. If the environment cannot render the planned effects, lower fidelity openly or report the blocker—don't relabel 2.5D as 3D.

## Objective checks on the actual encode

Use established renderer-skill commands, not guessed flags. Probe stream codecs, actual dimensions, frame rate/count, duration, audio presence/channels/start offsets and color tags. Decode the entire finished file. Compare expected versus actual composition coverage and source audio duration. For exact unedited narration preservation, compare copied stream/decoded PCM where practical; encoding may change packet identity so state what was actually compared.

Verify first/middle/last visible frame, both sides of edits, densest text, annotation onset/settle, camera transitions, end-card build and the audio tail. A clean source still does not verify H.264 color, scaling or AAC timing. Check peaks/nonzero audio if appropriate, but energy/loudness measurements do not establish intelligibility or a listening pass. Never add normalization, music, replacement voice or cuts without scope authority.

## Visual acceptance checklist

- [ ] One main focal point; proper negative space; readable final-frame crop at target size and phone-size preview.
- [ ] Serif/mono hierarchy and locally loaded font behavior stable; no missing glyphs, broken line breaks or blurred essential type.
- [ ] Actual data/quotes/attribution match approved evidence; illustrative diagrams/counts labeled. Uncertainty remains visible and spoken where material.
- [ ] Red/amber/blue roles deliberate, readable and redundant with non-color cues. Dark metal is not crushed into background; paper isn't overexposed.
- [ ] Important connector reaches correct endpoint; changed state occurs at the right explanation; no unrelated loops compete with reading.
- [ ] Every entrance settles; sufficient hold before exit; no half-visible key phrase during a smear or stamp.
- [ ] Geometry has coherent scale, hinge pivot, intersections, perspective, occlusion, contact/shadow and camera clipping; no z-fighting/reflection mismatch.
- [ ] No visible private data or deceptive fake evidence. Archive/source credit and reconstruction/illustration label used where needed.
- [ ] Full narration and intended tail retained; no visual-sequence restart/duplication, mute gap or accidental blank tail.
- [ ] Final conclusion precedes CTA; ending holds intentionally; style metadata absent unless requested.

## Delivery / persistence

Use workspace Videos/<project>/ with editable src/assets/public, exports, proof and notes. Keep final discoverable at the project top level when current user directives require it; preserve exact delivered filename and older versions. Report local saved file != committed/synced. Do not commit/push, post or redistribute automatically.

Production notes must state: original identity, actual tools/versions, chosen source evidence IDs, proposed tokens/settings, narration and cue basis, source/program cut map if any, approval state, encoded-output tests, frames reviewed, audio listening status, rights/privacy status and remaining gaps. If only a plan/spec was requested, deliver that plan—do not manufacture a production-complete claim.
