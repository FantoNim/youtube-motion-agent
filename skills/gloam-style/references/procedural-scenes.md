# Procedural adaptation: 2D, 2.5D and genuine 3D

These are **proposed original constructions**, informed by [G01–G12](source-analysis.md), not recovered source assets/code or an already rendered Gloam demo. Do not claim execution readiness from this document. Read the active local Remotion workflow/runtime before writing code. The workspace has a separate synthetic ThreeCanvas 3D test; inspect its current manifest and verification report, not just this statement, before relying on it. It is not an approved Gloam sample.

## Pick the least complex honest representation

- Evidence cards, charts, metadata and timers: DOM/SVG in 2D. Keep type crisp and selectable/editable in source.
- Tilted paper with overlap/shadow or bounded parallax: 2.5D DOM transforms or camera-facing planes. Do not market it as modeled 3D.
- A doorway viewed through, rotating door, rows with viewpoint-dependent occlusion, or scene lights/materials: actual scene graph, perspective camera, geometry and lighting. In the existing local Remotion route that can mean ThreeCanvas/@remotion/three with compatible pinned Three/Fiber dependencies. Do not add packages or alter shared runtimes without separate authority.
- If genuine geometry cannot be rendered locally, choose a clearly labeled 2.5D variant or report the blocker. A generated picture with a camera zoom is a plate, not expanded real-3D capability.

## Shared construction contract

Record units, stage orientation, camera projection/FOV, object dimensions/parents, text role, light positions/colors, material intent, temporal state curve, sources and privacy. Drive all motion from frame/fps, with clamped progress and deterministic seeds if used. Do not use wall-clock timers, uncontrolled physics, random asset placement or live network resources. The included JSON schema is a production handoff, not an engine API.

### A. Evidence slab / folder — 2D or 2.5D (G03/G08/G10)

1. Make a matte off-white rounded-minimally or square paper panel; place chapter/metadata in a small upper band, a thin rule, one large statement or structured rows, a source footer and any meaningful qualification.
2. Define 2–3 layers only: background field, shadow/paper, ink/annotation. Use a slight angle if it doesn't distort type. For a dossier add a simple tab and anonymous silhouette area; never invent identity/evidence.
3. Reveal rows by narration order, hold, then add a short underline/circle/stamp. The stamp belongs to an actual analytic conclusion or a clearly labeled illustration, not a fake official verdict.
4. Export crisp text. Do not bake long paragraphs into low-resolution images. Pass if all important text/qualifiers are legible in the encoded phone-size preview and paper overlaps never hide them.

### B. Mechanism/authority diagram — 2D (G07)

1. Build three anchors: ordinary system, authorization/note, program/controller. Use simple original outline icons and concise labels.
2. Draw one outbound connector and one return/control curve only when the explanation needs it. Use endpoint/state labels; let the destination color/state change after the path reaches it.
3. Pause after the state change. Follow with a spatial metaphor only if the narration introduces that analogy. Pass if the direction and changed authority are understandable without color and the diagram does not imply unverified technical specifics.

### C. Vault-room metaphor — genuine geometry (G02/G04/G07)

Proposed starting proportions in arbitrary world units: room width 12, height 6, depth 16; doorway radius about 2; door slab thickness 0.35; coin radius 0.12 and thickness 0.035. These are practical defaults, not source measurements.

1. Room: floor, side/rear wall meshes and a coherent ceiling/strip-light cue. Create a circular opening from an explicit ring/portal assembly or a reviewed mesh; don't call an opaque disk with a painted hole a traversable portal. Use a short tunnel/ring depth so the threshold reads dimensionally.
2. Door: circular cylinder face with rim/bolts and a distinct hinge parent. Set a real hinge pivot at the side; rotate the door child about that pivot, not around the disk center. Give the wheel a separate axis only if it serves the action. Test the entire opening arc for intersections.
3. Props: instanced cylinder stacks for coins, rectangular plinth/tray, original simplified mannequin/robot if needed. Avoid claiming a single still is a rig. Use an approved procedural proxy or licensed asset; don't reproduce a real suspect's identity from anonymous source imagery.
4. Camera: establish room depth, then optionally cut or dolly to the threshold. A foreground edge and distant tray should move/occlude differently if the camera travels. Do not drive the camera through an opaque door or clip the figure.
5. Materials: rough industrial steel, matte wall, warm metal accent, restrained polished floor. Use key/fill/rim intentionally; add practical red only for changed status. Avoid chrome everywhere. Reflections may be simplified; never claim physically accurate ray tracing if a flat mirrored copy is used.
6. State: depletion follows a deterministic visible count/fraction. Hide/reduce stacks in a defined order or animate a small approved set. It is an illustrative metaphor unless values and mapping are audited. Do not use noisy falling physics to imply quantitative precision.
7. QA: inspect closed/half-open/open door and camera start/middle/end; geometry must show real silhouette, depth and occlusion changes. Check readable labels and no disappearing walls, z-fighting, shadow acne, floating feet or floor contact errors.

### D. Network of vaults — genuine geometry + 2D labels (G06/G09)

Create a reusable door/plinth group and instance it in a short row/arc with true depth separation. Place labels on front-facing plates or a crisp projected overlay; connect groups with deliberate line paths. A red practical/status point plus text/icon communicates changed state; keep inactive nodes subdued. Use a small fixed set of cameras/cuts or one tested lateral move. Readable relationships matter more than perfectly matching source reflections. Pass if foreground units occlude background units consistently, connectors meet the intended node, and labels remain stable when the viewpoint changes.

### E. Cash-register and storage arrays — geometry variant (G04/G11/G12)

For an original domain metaphor, a stylized register can be boxes/cylinders with a lever/button silhouette and a small tray, with instanced stacks around it. It need not be a detailed antique model. Storage arrays can be repeated matte boxes with a thin warm status strip and clear labels. Preserve count/order across return shots. Freeze unnecessary movement when speech says the objects are still. Pass if quantity/status changes are intentional and a return shot matches the initial scene's topology.

## Renderer/color/fidelity guardrails

Keep generated data text in DOM/SVG overlays where practical. Confirm Three renderer output/tone mapping against the encoded Rec.709 output; don't assume CSS and material colors will match automatically. Avoid baking source-like darkness until silhouettes disappear. Use real local render stills and a short encoded moving sample to decide whether shadows/reflection cost is justified. Rebuild with original assets, not screenshots ripped from the reference.
