# Local Remotion 3D Scenes

1. **Inspect the brief and project first.** Read the existing source, manifest, lock, assets and destination before writing. Use the broader remotion-motion-graphics workflow for narration, editorial timing and production approval. Record aspect ratio/fps/duration, shot purpose, camera path, asset/license inventory and audio policy. Without supplied narration, label autonomous tests silent and synthetic; never fabricate speech, music or style approval. **Done:** brief states whether this is a technical test or approved production.

2. **Check the exact local runtime and license.** Read [references/runtime.md](references/runtime.md). Inspect dependency manifests, node_modules links/junctions and npm cache. All Remotion packages must match; React 19 needs R3F 9. Reuse compatible installed packages/browser read-only; never install through a shared node_modules junction. If packages are missing, use an isolated project and reviewed exact package-lock, registry-only integrity review, then task-authorized npm.cmd ci --ignore-scripts --no-fund --no-audit. No global install, broad shared-runtime edit, cloud renderer, remote media/font fetch or paid API. The skill/template license does not grant Remotion business eligibility. **Done:** versions, installation scope, license basis and browser executable are recorded.

3. **Start with the tested template, not a custom engine.** Read [assets/template/README.md](assets/template/README.md) and copy its editable source/manifests/helpers into a new empty project under Videos/<project>/; preserve originals and versioned outputs. The template follows official ThreeCanvas/Composition patterns and contains procedural coffee-shop geometry, no stock downloads. Adapt this set rather than assuming it matches any reference style. Keep src/, public/ if needed, exports/, proof/ and notes/. **Done:** project has complete local source + pinned lock; no existing project was overwritten.

4. **Drive every transformation from the frame.** Read [references/scene-patterns.md](references/scene-patterns.md). Use ThreeCanvas with explicit width/height and dpr, useCurrentFrame and pure frame/fps math; no useFrame accumulated motion, interactive OrbitControls, unseeded randomness or wall clock. Position/aim the camera synchronously before capture (tested useLayoutEffect rig), with deliberate parallax between foreground and background. Inside ThreeCanvas, Sequence requires layout="none"; DOM overlays belong outside it. Use real geometry/materials/lights and castShadow + receiveShadow, not flat perspective CSS claimed as 3D. **Done:** seeking to the same frame reproduces camera/object transforms; silhouettes, lighting and foreground/background separation are intentional.

5. **Prove the Chromium renderer is not black.** Set chromiumOptions.gl explicitly on Node render APIs; a CLI config does not apply there. Try supported desktop angle first; if unavailable, reviewed swangle software fallback is allowed but must be labeled. Capture WEBGL_debug_renderer_info where supported; angle alone does not prove GPU acceleration. Inspect actual rendered PNGs and scene-region luminance/variation, not only logs or a colored DOM background. Record actual renderer, browser version, shadow enablement and backend. Keep preview/render servers loopback-only. **Done:** real 3D appears in first/middle/end images and exact backend/acceleration evidence is saved.

6. **Verify a short encoded sample before production.** Typecheck, run the template self-test and render a 4–6s technical MP4. Run the independent verification helper: ffprobe dimensions/fps/count/duration/audio policy, full FFmpeg decode, encoded first/middle/end extraction, repeated raw-pixel frame hash, and camera projection/parallax report. Inspect extracted PNGs with view_image; compare foreground/background feature displacement, shadow visibility, occlusion, legibility and framing. Do not call formula-only parallax encoded verification. For narration, retain the existing audio verification gate from remotion-motion-graphics. **Done:** actual encode passes objective checks and fresh encoded frames have been reviewed; remaining playback/listening limitations are explicit.

7. **Record readiness and deliver truthfully.** Read [references/verification.md](references/verification.md). Report docs-only, still-tested or encoded-render-verified separately from artistic/style approval. Save reproducible commands, runtime/lock/license evidence and limits in notes/production-notes.md; keep a discoverable top-level copy of the exact export filename. Check Git ignore/tracking state; local files are not automatically synced. Run skill-creator quick_validate.py and all touched helper tests after skill changes. **Done:** MP4, complete editable source, proofs and exact reproduction path exist; no long production or reference-style approval is implied.
