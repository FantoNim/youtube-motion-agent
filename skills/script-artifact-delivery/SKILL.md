# Versioned Artifact Delivery

1. Identify whether the task is new drafting, a revision, approval, retrieval, or delivery. Inspect existing folders/artifacts first. Approval or a request to resend a final is not permission to regenerate it.
2. For scripts use Scripts/<project>/<video>/script-vNN.md with separate notes-vNN.md; for learner copy use Lessons/<course>/<lesson>/. Choose the next unused version. Keep source citations, privacy evidence and technical notes separate from learner-facing text. Read the relevant production skill before making new media.
3. Write the complete requested artifact, then read it back and verify required content, version, opening and ending. If the user wants full text in chat, provide it there as requested as well as saving it.
4. For existing images/video, match distinguishing content and exact delivered basename, inspect the actual artifact, and verify metadata/hash. Copy exclusively only when relocation was requested; compare destination first and never overwrite a different file. Preserve approved immutable assets.
5. Attach using the current destination surface's real media contract. A prose path is not proof of a playable attachment. Include the exact saved path and be clear whether the artifact is saved, attached, Git-tracked, committed or remotely synced. No automatic public upload.
6. Record approvals separately from render/QA status. Deliver a representative sample for its outstanding style approval; after approval continue the same project without resetting the task. If delivery fails, recover the verified finished artifact rather than needlessly re-rendering.
