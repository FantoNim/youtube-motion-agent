# Examples, planning prompts and adaptation boundaries

These examples are original hypothetical adaptations, not shots observed in the source. They are planning instructions, not tested code, executable prompts or a promise that a media-generation service is configured. Use a verified local implementation; do not invoke hosted generation/upload merely because a prompt is included.

## Example A: an information overload story

Narration idea: a person accepts every notification, then cannot identify the important one.

- Establish a small office/workshop in a warm-purple evening. Place a pale spherical-headed original generic protagonist in a blue rounded jacket at a simple desk. Show the actual approved message/notification concept as a framed prop, not a full-frame screen recording.
- Medium three-quarter shot: an initial confident half-lidded expression and one deliberate open-hand explanation gesture. Let a small pink cue mark a newly relevant task; no invented numerical claim.
- Reverse/closer shot: several cues now compete; eyes/brows become uncertain, hands stop rather than waving harder. Keep the cast identity and set geography stable.
- Purple explanation board: two labeled columns, “everything” and “important,” one gold heading, one highlighted decision; use supplied truthful counts only if they exist.
- Return to the same set for the consequence: one selected task, calmer pose and a readable hold. Timing follows the supplied recording, not these bullets.

## Example B: a quiet reaction before a diagram

A character has just misunderstood a friend's silence. Hold a worried expression with lowered hands in a simple room; do not use a happy face because the topic is “communication.” Cut to a diagram with two people and one labeled relation (“assumption,” not an unexplained beam), then return to the person choosing a better question. If a line is metaphorical, label the conceptual nature. This borrows staging and graphic relationships without copying the romance plot or the original research claims.

## Example C: scope-limited lower-cost adaptation

For a fixed-view lesson, use original rendered character pose images on layered set planes plus gold type and a pink relationship line. Avoid head/body turn claims, arbitrary reverse angles and light sweeps inconsistent with the baked images. Call it “Jeremy-inspired 2.5D adaptation,” not a full real-3D reproduction. Approve the compromise before a long render. If the user needs walk-throughs and moving-camera occlusion, choose real geometry instead.

## Prompt patterns for planning

**Shot director:**
“Use Jeremy Style as defined in the local guide. Given the verified narration interval [start/end] and thought [meaning], plan one scene. State what the viewer learns, dimensional class, original cast identifiers, exact expression/hand/body pose, simple set, camera/eye line, light/material roles, information overlay and transition cause. Separate source-observed grammar from proposed numeric defaults. Do not invent narration, word timing, statistics, branded assets or a new host likeness.”

**Character consistency reviewer:**
“Compare this model sheet and encoded proof with the approved original cast/host brief. Check head/body proportions, clothing/identifier, dark graphic face readability, tooth-free speaking mouth where required, pose diversity and contact points. Report concrete faults with frame/time; do not call a pose-rig implemented just because multiple static images exist.”

**Meaning-led QA:**
“For each shot, compare the actual recorded phrase and the visible action. Identify irrelevant motion, unreadable labels, camera geography errors, line/counter meanings, unsupported quantitative claims and insufficient reaction holds. Prioritize meaning, then reading time, then polish. Do not infer music, timbre or mixing quality from images.”

**3D readiness reviewer:**
“Inspect the actual local project's manifests, scene source and short encoded test. Establish which 3D dependencies, geometry, camera, materials, light, rig and deterministic animation are really implemented. Distinguish a plan, a single-frame render, a working animated sample and user-approved full production. Do not install software or mutate shared runtime configuration to pass the check.”

## Scope and originality

Keep the style recognizable through spatial toy figures, emotional acting, purple/warm lighting and restrained explanatory graphics—not a shot-for-shot rebuild. Use an original story and assets. A scene prompt must not request the source narrator's identity, exact proprietary models, reconstructed logos or copyright redistribution. Style adaptation has no guaranteed audience-performance outcome.
