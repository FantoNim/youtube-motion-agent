# Screenplay before a style sample

When a user requests a movie script before a Jeremy Style sample, finish the writing phase before opening a render or generating assets. A named style or a screenplay request is not sample approval.

1. Inspect the actual source audio streams, starts and duration. Use the approved local ASR workflow when needed; read the complete requested transcript. Keep raw speech evidence private. Mark uncertain names explicitly rather than silently fixing homophones or treating segment times as word alignment.
2. Preserve the supplied narration as the timing master. Build a scene-to-narration map including pauses, the final phrase and full source tail. Do not rewrite, extend, speed-change or replace the recording to fit a story unless requested.
3. Write the dramatic premise before designing shots: an original protagonist wants something concrete; a visible obstacle blocks them; they make a choice; an action produces a consequence; the ending pays off an earlier image. Avoid a collection of unrelated word illustrations or automatic caption cards.
4. Save a versioned movie-style screenplay under Scripts/<project>/<video>/. Beside each actual narration thought, specify setting, action, expression/pose change, camera purpose, transition cause and scene dimensional class. Distinguish proposed staging/metaphors from facts in the recording and from tested renderer behavior. Keep source citations, qualifications and production constraints in separate notes.
5. Check story logic against the message. An example of applying skills in another tool should not accidentally celebrate the tool-hopping the film criticizes. Explicitly motivate a later-use vignette if needed. Maintain room geography, prop resting places and character identifiers; fit a readable number of actions into the measured window. Treat mastery compressed into a few seconds as illustration, not an outcome claim.
6. Use a compact board only where it explains a mechanism the acting cannot show clearly. Define the recurring line's meaning. Use no invented numbers, unsupported product capabilities, magical compatibility checkmarks or claimed file interoperability to illustrate transfer of knowledge.
7. Validate consecutive timeline coverage, transcription fidelity (with uncertain words marked), local resource links, full ending and source integrity. Save planning data as not execution-ready until implementation exists. Read the screenplay back and deliver its actual versioned artifact with a brief story summary and only material uncertainties.
8. Stop for script review when that is the requested gate. Recommend a representative sample interval if useful, but do not start it. After script approval, follow the renderer, sample and encoded-QA procedures; a screenplay is not animation or aesthetic approval.
