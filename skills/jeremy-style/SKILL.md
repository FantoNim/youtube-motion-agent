# Jeremy Style

1. Establish the request and protect the source.
   - Distinguish reference analysis, storyboarding, a short sample and full production; a style request alone does not authorize a render. Read the current project and USER.md before creating files; preserve prior versions and immutable avatar masters.
   - Read [source evidence and limits](references/source-evidence.md). Keep reference media, extracted frames and raw ASR private; never redistribute the source or treat its claims as verified research.
   - **Done:** versioned project notes name the outcome, audience, dimensions, approval gate, source/privacy boundary and unknowns.

2. Choose the dimensional treatment honestly.
   - Read [visual grammar](references/visual-grammar.md) and [procedural scene recipe](references/procedural-scenes.md). The reference is predominantly volumetric 3D storytelling with flat/2.5D explanation inserts—not flat stick figures or only CSS perspective.
   - Choose full 3D for spatial staging/turns/occlusion, a deliberately labeled 2.5D adaptation for fixed-view cutouts, or a hybrid. Do not imply source project files prove its authoring engine.
   - If the user's own host appears, apply the current approved likeness rules; a new spherical-head derivative needs explicit approval. Use an original generic cast otherwise; do not insert a host unnecessarily.
   - **Done:** each scene has a documented 2D/2.5D/3D class and a reason; any fidelity compromise is disclosed.

3. Lock narration before pictures.
   - Use the supplied recording as timing master, preserving it unless edits are authorized. A script is optional. Probe actual audio duration/offsets; use an existing local ASR workflow only when needed and check names, meaning and decisive sync points.
   - Read [motion, editing and voice timing](references/motion-and-timing.md); plan meaning-led beats rather than wall-to-wall captions or arbitrary cut quotas.
   - When a screenplay is requested before a sample, follow [screenplay-first planning](references/screenplay-first.md): write the original character/action/consequence story beside the actual narration, save it with separate evidence/production notes, and stop for the requested script review before rendering. A script remains optional otherwise; apply current user directives.
   - **Done:** a verified/qualified transcript and narration coverage map include the last word and intended tail; any requested screenplay is saved and delivered before a sample; music/timbre claims have actual listening evidence or are omitted.

4. Create a reproducible scene plan.
   - Fill [shotlist template](assets/shotlist-template.csv) and [scene brief template](assets/scene-brief-template.json); consult [examples and prompt patterns](references/examples-and-prompts.md).
   - Specify character identifiers, expression/pose, information purpose, light direction, material roles, camera placement, focal plane, overlay hierarchy, transition cause and timing basis. Mark numerical choices as adaptation defaults, not measured source values.
   - **Done:** every shot can be built from an explicit brief, uses approved assets, and has one readable focal purpose.

5. Implement with a verified local renderer.
   - Read remotion-motion-graphics for graphics production and local-video-editorial for shot review. For genuine geometry/camera work, read remotion-3d-scenes and its current verification evidence; its coffee-shop fixture proves a local rendering path, not this character rig or a faithful Jeremy Style sample. Check the existing project's manifests, license, actual 3D dependencies and runtime before selecting an implementation. Read Filmcraft only when native assembly is needed.
   - Follow the deterministic frame-clock, camera/rig/material and performance guidance in the procedural recipe. Do not install globally, use paid APIs, upload media, or claim an untested recipe is working code. Pre-rendered 3D plates are not native editable NLE rigs.
   - **Done:** a minimal local scene renders, its source is editable, and actual readiness/fidelity limits are recorded.

6. Approve a representative sample.
   - Produce a short sample containing a character reaction, spatial camera view, pink-line/metric information cue and a gold-on-purple explanation insert, adjusting the selection to the actual brief.
   - Read [rendering and QA](references/rendering-and-qa.md). Review encoded motion across cuts, text readability and narration sync; a still/contact sheet alone cannot approve motion. Obtain sample approval before full production unless waived.
   - **Done:** the sample and proof exist, checks are recorded, and approval is explicit or pending—not assumed.

7. Render, inspect and deliver only the requested scope.
   - Verify actual encoded streams, duration, whole-file decode, boundary frames, expressions, contact/occlusion and audio continuity. Fix faults, then inspect fresh outputs. Keep the style label out of learner-facing frames unless requested.
   - Save editable source, assets/license notes, shotlist, scene briefs, encoded output and review evidence in an organized versioned project; do not put private reference frames into public assets.
   - **Done:** the requested artifacts exist, validation passes or precise blockers are reported, and the handoff states real coverage, approval and any untested claims.

This documentation bundle contains no renderer, automatic asset downloader, speech model or execution-ready demo. For analysis-only use, finish after the evidence-backed specification and its file/link validation; do not start a production sample automatically.
