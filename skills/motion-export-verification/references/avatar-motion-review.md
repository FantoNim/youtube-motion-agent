# Articulated avatar and camera-return previews

1. Hash the approved character master before producing derivative layers, because pose authorization does not authorize replacing the likeness. Preserve the master and record each runtime derivative in asset notes. Segment torso, head and forearm/hand separately for a cut-out puppet; remove the old arm and pupils only in derivative layers, because retaining them creates duplicate limbs or fixed gaze.

2. Define a semantic pose inventory and render bounded proofs before integrating the main timeline, because changing a face while rotating the same open hand does not establish different body gestures. Hold the face constant in a comparison sheet and verify distinct hand silhouettes, arm positions and body intent for the requested pointing, thinking, confident, happy, explaining and neutral poses. Use an extended index for pointing, a hand near the chin for thinking, a waist/hip stance for confidence and genuinely different celebratory hands for happiness when those poses are requested. Preserve the likeness in derivative layers; do not invent a replacement identity. Inspect attached shoulders, elbows and wrists, finger silhouettes and front/back layer order at each pose extreme, because floating hands, duplicate old arms and exposed joints can pass a typecheck. Drive independent pupil/head movement for directed gaze; describe it as a 2D glance rather than 3D tracking or phonetic lip sync. Apply wave-cycle and camera-return checks only when the brief requests those actions.

3. Read the component's time contract and convert timeline frames to pose-relative frames at its expected fps, because a global clock or an assumed frame rate can skip every entrance. Record anticipation, entry, settle, hold and exit bounds for each semantic pose. Return through the component's supported neutral exit before changing discrete hand silhouettes unless an intentional editorial cut calls for a pose cut, because swapping poses mid-hold can teleport wrists or fingers. Give each requested action enough time to settle and hold; inspect pose-entry resets across scene cuts instead of restarting every gesture mechanically.

4. Give a delegated asset builder the real inset side, avatar/inset bounds, target center and pose durations before proofing, because a placeholder alone cannot establish pointing direction or available settle time. Check the actual hand aim and pupil offset against the integrated target, not merely an arbitrary left/right prop. Keep asset/component proof files separate from the main timeline and serialize their renderers with the parent under memory pressure, because per-process concurrency does not bound total memory.

5. Render the articulated proof on both light and dark backgrounds with the installed CLI, because segmentation halos and joint seams can hide on one background:

       remotion render src/avatar-proof.tsx AvatarProof proof/avatar-motion-v001.mp4 --bundle-cache=false --concurrency=1 --scale=SCALE --codec=h264 --pixel-format=yuv420p --crf=20 --muted
       ffmpeg -v error -i proof/avatar-motion-v001.mp4 -f null -
       ffmpeg -v error -n -i proof/avatar-motion-v001.mp4 -vf "select=eq(n,ANTICIPATION)+eq(n,OUTWARD)+eq(n,INWARD)+eq(n,SETTLED)" -fps_mode vfr proof/avatar-phase-%03d.png

   Substitute measured integer phase frames and use view_image on actual encoded anticipation, extremes, settled holds, exits and reset endpoints, because typechecking and alpha bounds alone cannot expose layer-order defects. Add every requested pose and direction; include wave-cycle extremes only for an actual wave. Render a new version after fixes and inspect that encode rather than reusing superseded proofs.

6. Render a narrated continuous integration sample covering representative new gestures and the actual screen/graphic target, because isolated silent pose proofs cannot approve the production choreography. Match pose changes to the narration's meaning rather than cycling every available emotion into one sentence. Follow the brief's screen-size policy, preserve graphics as the primary explanation when requested, and inspect the real screen cue and source-clock mapping. Use portrait-previews.md when applicable for inclusive range, exact scale, audio excerpt and sync checks. Inspect encoded contact sheets and native-size dense frames for pointing/gaze direction, legible important text, privacy masks, cropped-screen placement and limb continuity. Request approval of the new motion before full production even when an earlier video established the palette.
