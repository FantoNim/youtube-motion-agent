# Narrated motion export verification

1. Read the applicable renderer skill and project manifest before rendering, because this verification procedure supplements rather than replaces the production workflow. Save evidence under the project's notes/ and proof/ folders and version exports without overwriting approved samples.

2. Inspect original and extracted media with ffprobe -v error -show_streams -show_format -of json INPUT, because measured stream duration and start offsets determine the timeline. Record the original file hash and preserve the original file. Set frames to ceil(measuredSeconds * fps), and record any rounding tail rather than stretching narration.

3. Extract a compatible original AAC track with ffmpeg -n -i INPUT -map 0:a:0 -c:a copy narration.m4a, because stream copying avoids unnecessary audio loss. Render picture separately and mux the full master with ffmpeg -n -i PICTURE -i narration.m4a -map 0:v:0 -map 1:a:0 -c:v copy -c:a copy -movflags +faststart FINAL.mp4. Omit duration limits and -shortest so the source ending is not silently cut. Verify offsets before applying this zero-offset example.

4. Map each spoken showcase cue to the user-selected media before rendering, because an available asset from a prior project may not be the intended example. Start the selected example when the speaker introduces its genre or subject and retain it through the pointing phrase; record the source excerpt and program interval, preserve geometry, and inspect encoded frames to confirm the correct clip appears. Select a continuous, representative narration interval for style review, because a title-only sample does not establish the visual treatment. Record source start/end seconds, inclusive output frame bounds, and expected duration. Use references/portrait-previews.md when scaling a portrait preview, because calculated integer dimensions and source-clock bounds prevent avoidable render retries. Re-encode an excerpt only when necessary for accurate sample boundaries; label it as an excerpt rather than bit-identical full narration. Compare decoded source-interval and sample waveforms, including start, middle, and end lag, because matching container lengths alone does not prove synchronization.

5. Probe the raw picture before mastering, because a requested pixel format does not prove actual color range or matrix. For a confirmed full-range BT601 picture targeting limited-range BT709 SDR, convert pixels with ffmpeg -n -i RAW -vf "scale=in_range=pc:out_range=tv:in_color_matrix=bt601:out_color_matrix=bt709,format=yuv420p" -c:v libx264 -crf 17 -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 -an PICTURE.mp4. Use conversion settings supported by the measured input; do not apply this example to an unverified source. Check pixel format, range, matrix, transfer, and primaries in the encoded output. If the converted H.264 bitstream still lacks signaling, use the h264_metadata bitstream filter to set colour_primaries=1:transfer_characteristics=1:matrix_coefficients=1:video_full_range_flag=0, because this repairs metadata only after genuine pixel conversion. Compare decoded RGB proof frames against the approved sample so mastering does not materially change the palette.

6. Hash original, extracted, and final AAC packet streams with ffmpeg -v error -i INPUT -map 0:a:0 -c:a copy -f adts - followed by a local SHA256 calculation, because matching packet hashes prove full compressed-track preservation. Compare complete decoded audio arrays when available and report peak, RMS and decoded full-scale-exceedance counts for both source and output using identical channel/rate settings, because a hot original must not be mistaken for new export damage. Decode comparable float samples with ffmpeg -v error -i INPUT -map 0:a:0 -ac 1 -ar 16000 -f f32le -, selecting the same source interval for an excerpt. Investigate any output overage against source peak, energy, waveform lag and sample counts before changing audio; distinguish decoded values beyond ±1 from proven flattened clipping. Preserve unrequested source levels and record inherited overages as warnings, because silently normalizing or limiting changes the authorized narration. Require full-track packet/PCM identity for a claimed lossless final; use documented source-relative tolerances plus start/middle/end correlation for a re-encoded excerpt. Investigate timestamp or duration differences against packet/sample identity before calling them truncation or rounding. Describe an objective waveform check as such, not as a listening pass.

7. Count encoded frames with ffprobe -v error -select_streams v:0 -count_frames -show_entries stream=nb_read_frames,width,height,r_frame_rate,duration -of json FINAL.mp4 and decode the complete file with ffmpeg -v error -i FINAL.mp4 -f null -, because source typechecks and composition metadata cannot establish export integrity. Require expected video and audio streams and continuous coverage of the measured narration.

8. Extract actual encoded proof frames with ffmpeg -n -ss SECONDS -i FINAL.mp4 -frames:v 1 proof/FRAME.png, because source stills miss encoding defects. Inspect every scene, transition boundaries, first and last frames, and dense labels with view_image. For elastic motion, add anticipation, maximum overshoot, squash/stretch, recoil, and settled frames so offstage geometry and label collisions are caught. For articulated avatars or camera-return gaze, follow references/avatar-motion-review.md to verify actual joint movement, layer ordering, pose holds and the real inset direction before requesting motion approval. Fix failures, render a fresh version, and inspect the new encode before delivery.

9. Disable bundle caching from the first render when reusing a shared dependency junction: use --bundle-cache=false for the Remotion CLI or enableCaching: false in the Node bundle API, because default bundling can modify another project's cache. Follow [approved-sample expansion](references/approved-sample-expansion.md) when extending an approved sample into a full film, because compatible picture-only reuse needs codec, frame-partition, timestamp and decoded-frame preservation checks before final audio mastering. Keep temporary render files inside the active project and never install dependencies through the junction. Run picture render processes serially under memory pressure, because concurrency=1 limits only each process, not all active jobs. When resource constraints require segmented picture renders, record inclusive frame ranges and verify they partition the full timeline exactly; reuse an approved compatible picture segment without its excerpt audio, then mux one continuous original audio track afterward so segment seams do not restart narration. If OffthreadVideo reports missing frames at changing valid source positions, inspect source PTS and available memory before changing media; use only installed, inspected cache/thread flags within available RAM. If retries remain unreliable, extract the affected CFR source range to lossless PNGs with ffmpeg -n -i INPUT -map 0:v:0 -frames:v COUNT -fps_mode passthrough public/source-frames/frame-%04d.png, map Img to String(sourceFrame+1).padStart(4,'0'), verify count and decoded RGB correspondence, and retain the original audio separately; this avoids the failing cache without altering source cadence.

10. Deliver the approved sample for style approval before the full production export, then continue the existing task after approval rather than asking again. Keep all finished exports in organized project folders inside the active agent workspace/repository, because this workspace is shared across devices through Git. Put a discoverable final file at the workspace project-folder top level, retain editable source and render intermediates in subfolders, and use video_clips/<project>/ for clipping outputs. Do not copy to Documents or an external source-media folder unless specifically requested. Check git check-ignore and git status for each final artifact, because being inside the workspace does not make a file tracked, committed or synced; keep temporary renders ignored and report the actual Git state. Preserve the delivered basename, such as final-v001.mp4, when copying or locating it; do not invent a friendlier replacement name unless requested, because the user may search for the exact filename already delivered. Inspect the destination before copying; use an exclusive copy such as fs.copyFileSync(source, destination, fs.constants.COPYFILE_EXCL), accept an existing file only if its SHA-256 matches, and never overwrite a different file. Compare source and destination SHA-256 and list the destination after copying, because completion requires a verified accessible artifact rather than a proposed location. Include the exact absolute path of the final audio-bearing export in the same completion message as its attachment, because the user may need to open the saved file directly and must not be sent to a silent picture intermediate. Attach each delivered sample or final through the active surface’s native message media field, such as message(action="send", media="<verified-absolute-path>"); use attachments for multiple files, because prose paths alone do not deliver a playable approval artifact. Follow the current surface contract rather than assuming a legacy MEDIA marker is rendered. Follow [completed-export handoff recovery](references/completed-export-handoff.md) for a delivery error, repeated intermediate completion, or a request for the finished file path, because these require reconciling the verified export rather than restarting production. Label a sample as a sample and request only the outstanding approval; after approval, continue the same project without asking again. Deliver only a verified finished export as final, and keep sampled visual review, continuous playback, human listening, and machine timing evidence distinct so completion claims match the checks performed.
